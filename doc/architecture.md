# Architecture

## Purpose

HyperTodo proves that a normal Django project can install dj-hyperview and own a mobile interface whose source comes from project XML files, database records, or cache. The package contains the serving infrastructure; this consumer owns every screen and domain decision.

## Runtime shape

```text
Expo/Hyperview client
        |
        | application/vnd.hyperview+xml
        | Django session cookie + CSRF form field
        v
Django HXML endpoints
        |
        +-- TODO models, forms, selectors, and mutation services
        |
        +-- dj-hyperview resolver
              |
              +-- DatabaseSource, first
              +-- FileSystemSource, fallback
              +-- Redis cache, optional
```

The API is HXML-only. There is no parallel JSON resource API and no client-side domain state store.

## Domain model

A `Category` belongs to one user, has a case-insensitively unique name within that user, and selects one color from the visual palette. Deleting a category preserves tasks by setting their category to null.

A `Task` belongs to one user and may reference one of that user's categories. It contains a title, optional notes, optional timezone-aware deadline, and optional completion timestamp. Completion is derived from `completed_at`; there is no redundant status column.

Every read and mutation begins with the authenticated user. A foreign identifier returns 404 rather than revealing that the object exists.

## Endpoint contract

All application routes live under `/hv/`. They accept only GET and POST because Hyperview forms and behaviors need screen or fragment responses rather than REST semantics.

- `/hv/` chooses login or dashboard without redirecting.
- `/hv/login/` returns the dashboard on the same successful 200 response that establishes the session cookie.
- `/hv/logout/` returns the login screen directly.
- `/hv/dashboard/`, `/hv/tasks/`, and `/hv/categories/` serve private screens.
- New, edit, toggle, and delete endpoints return refreshed HXML directly.
- Invalid form submissions return HXML with status 422.
- Expired sessions return a dedicated HXML screen with status 401.
- Unsupported methods, missing objects, and CSRF failures remain HXML responses.

Avoiding authentication redirects is intentional: React Native can fail to persist a cookie delivered through an iOS 302 response.

## Deadline representation

Hyperview 0.110.0 exposes a date field but no native time field. The task form therefore submits `due_date` as YYYY-MM-DD and `due_time` as validated HH:MM text. Django combines them in the configured timezone. A time without a date is invalid; a date without a time represents local midnight.

## Template ownership and precedence

Physical defaults live in `backend/hyperview/screens/`. Settings configure the database source first and filesystem second. An active database row whose canonical name exactly matches a physical template overrides it immediately. Missing or inactive rows fall through to the physical file.

Database edits trigger dj-hyperview's commit-aware invalidation. Physical file edits cannot emit that signal; while Redis caching is enabled, invalidate the affected template or temporarily disable cache during active XML development.

## Redis isolation

HyperTodo reuses the existing Redis service instead of owning a container:

- development cache: `redis://127.0.0.1:6379/15`
- integration tests: `redis://127.0.0.1:6379/14`
- development namespace: `dj-hyperview-test-dev`
- tests: a unique `dj-hyperview-test-tests:<uuid>` namespace per run

No command flushes a logical database, and this project never starts, stops, or reconfigures the shared Redis service.

## Mobile shell

The Expo app supplies the pieces that are outside server-driven markup: navigation host, native module setup, splash lifecycle, backend URL, cookie-preserving fetch, and branded loading/error states. Narrow custom components and behaviors cover interactions that HXML does not express directly, including the animated side menu, swipe actions, and global snackbars. Django still owns targets, URLs, state, and outcomes; fixed native interaction labels remain presentation details in the shell. The shell does not duplicate domain state.

The fetch adapter preserves request headers generated by Hyperview, adds the HXML accept type and same-origin CSRF origin when absent, uses `credentials: include`, and disables transport caching. If native smoke testing exposes the documented React Native cookie-jar limitation, the bounded fallback is `@react-native-cookies/cookies`; it is not installed preemptively.
